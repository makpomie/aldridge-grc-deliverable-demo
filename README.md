Aldridge Financial Technologies — GRC & ISMS Deliverable Set

A fifteen-document portfolio build: a four-policy suite, an ISO/IEC 27001:2022 gap analysis with a full Statement of Applicability, a NIST SP 800-30 risk assessment, a third-party risk assessment across three suppliers, a security awareness programme, and the master system prompt used to critique and refit the set as a senior GRC practitioner would.

[!WARNING] Portfolio demonstration. Aldridge Financial Technologies and all named individuals, vendors and figures are fictional, created to demonstrate a GRC and cybersecurity deliverable set. No real organisation's data is represented.

What this demonstrates
A shared context artefact that every deliverable reads from and writes back to, so figures reconcile across documents instead of drifting.
Evidence, effort, cost and dependency tracking attached to every finding, not a maturity rating asserted without a basis.
A capacity check that surfaces a remediation plan is not deliverable as assigned, before anyone approves it.
An expert critique pass that scored the first draft against practitioner standards, then drove a more rigorous second build — including catching that the set had assessed a regulated money transmitter without once mentioning sanctions or AML.
A note on the unsigned and draft documents

Three policies and two registers are deliberately left unapproved or unsigned: the Statement of Applicability, the Risk Treatment Plan, and the Acceptable Use, Data Classification and Third-Party Risk Management policies. ISO/IEC 27001 clause 6.1.3 requires risk owner sign-off and an approved Statement of Applicability before an ISMS is certifiable — simulating that approval would misrepresent where the fictional organisation actually stands. See MANIFEST.md for the full status list.
